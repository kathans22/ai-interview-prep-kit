# AI Interview Prep Kit

Paste a job description and a company URL; get a research-backed interview preparation
kit — the requirements, questions that cover every one of them, flashcards, a day-by-day
schedule, and a practice mode — built from what the posting and the company's own pages
actually say.

> The rest of this README (architecture, decisions, the batch command, known limitations)
> is being written in a later stage. This first section is how the app is deployed.

---

## Deployment

Both halves run on free tiers.

```
browser ──https──▶ Netlify  (static web client, and a proxy for /api/*)
                       │
                       └──https──▶ Render  (Express API, background kit builds)
                                      ├──TLS──▶ MongoDB Atlas  (free M0 cluster)
                                      └──https─▶ Gemini API    (unbilled project)
```

The committed configuration is `render.yaml` (API) and `netlify.toml` (web client).
`test/deploy.test.js` holds `render.yaml` to `.env.example`: every variable in the
template is declared, production values are the safe ones, and no secret is committed.

### Why the web client proxies `/api`

The API is configured for a genuinely cross-origin client: CORS allows exactly one
origin, with credentials, and in production the session cookie is
`HttpOnly; Secure; SameSite=None`. But Safari on iPhone — and any browser with
third-party cookies blocked — discards a cross-site cookie, so sign-in would appear to
work and every following request would be a 401.

So the static site proxies `/api/*` to the API. To the browser the API is then
same-origin and the cookie is first-party everywhere. Calling the API directly still
works in browsers that allow cross-site cookies: set `VITE_API_BASE` instead of
`API_ORIGIN` on Netlify.

Because `SameSite=None` gives up the cross-site request protection `Lax` provided, the
API refuses any state-changing request whose `Origin` header names a site other than the
web client (`403 ORIGIN_NOT_ALLOWED`).

### 1. MongoDB Atlas

1. Create a free **M0** cluster.
2. **Database Access** → add a user used only by this app, with a long generated password
   and the built-in role **readWrite** on the database `ai_interview_prep_kit` only — not
   `readWriteAnyDatabase`, not `atlasAdmin`.
3. **Network Access** — how it is restricted, and why it cannot be restricted by address:
   Render's free web services have **no fixed outbound IP addresses**, so there is no
   address list to allow. The entry is `0.0.0.0/0`, and access is restricted instead by
   what a connection needs to succeed: that single least-privilege user and its password,
   over TLS (Atlas refuses unencrypted connections), to one database. Remove any other
   users and allowlist entries left over from development. With a paid Render plan's
   static outbound IPs, replace `0.0.0.0/0` with those addresses.
4. Copy the connection string and put the database name in its path:
   `mongodb+srv://<user>:<password>@<cluster>/ai_interview_prep_kit?retryWrites=true&w=majority`
   (the server warns at boot if the name is missing, because MongoDB would silently use `test`).

### 2. Gemini

Create a key at <https://aistudio.google.com/apikey>. **Keep its Google Cloud project
unbilled**: enabling billing on that project removes its free tier, and every call is
billed from the first token. Check under *Billing* in the Cloud console that the project
has no billing account linked.

### 3. Netlify — the web client (pick its address first)

1. **Add new site → Import an existing project** → this repository. `netlify.toml`
   supplies the build: `npm run build:web` from the repository root, publishing
   `apps/web/dist`, on Node 22.
2. Choose the site name; the address is `https://<site>.netlify.app`. The first build
   **fails on purpose** — it has no API to point at yet, and publishing a site that cannot
   reach its API would be worse.

### 4. Render — the API

1. **New → Blueprint** → this repository. `render.yaml` creates one free web service
   (`npm ci --omit=dev`, then `npm start`, health check `/api/health`).
2. Render asks for the values that are never committed:

   | Variable | Value |
   |---|---|
   | `WEB_ORIGIN` | `https://<site>.netlify.app` — exactly, https, no path |
   | `MONGODB_URI` | the Atlas string from step 1 |
   | `GEMINI_API_KEY` | the key from step 2 |
   | `SEARCH_API_KEY` | a Tavily key, or blank — the search then records an honest empty result |

   `SESSION_SECRET` is generated by Render. `PORT` is injected by Render.
3. **`ALLOW_PRIVATE_HOSTS` is `false`**, and the server enforces it: with
   `NODE_ENV=production` it refuses to boot if the value is `true`. That guard keeps a
   submitted company URL from reaching private, loopback or link-local addresses — the
   deploy's own network and the cloud metadata service. It is `true` only on a
   developer's machine, where the batch command's fixture sites are served from
   `localhost`.
4. Wait for the log line `listening on … (production)`, and note the service address,
   `https://<service>.onrender.com`.

### 5. Connect them

1. On Netlify, **Site configuration → Environment variables** → add
   `API_ORIGIN = https://<service>.onrender.com`, then **Deploys → Trigger deploy**.
   The build log ends with `redirects: wrote … (proxy /api → https://<service>.onrender.com)`.
2. Open `https://<site>.netlify.app/api/health`. It should return
   `{"ok":true,"env":"production",…}` — that request went through the proxy to the API.

### 6. Verify

From a private window, on the Netlify address: register, create a kit and watch it build
to the end, edit a question, regenerate a section, and practise the flashcards.

### Cold starts on the free tier

**The API sleeps after 15 minutes without traffic.** The first request after that waits
while Render starts the service again — typically 30 to 60 seconds. On a phone this looks
like a sign-in button that does nothing for a while. It is not broken:

- If the first page load or sign-in fails with a gateway error, the proxy gave up waiting
  before the API was awake. **Wait a minute and try again**; the second attempt is fast.
- To avoid it before a demo, open `https://<site>.netlify.app/api/health` a minute
  beforehand.
- Once awake, the service stays awake while it is being used — watching a build counts.
- A kit build running when the service restarts is marked **interrupted** at the next
  boot, and can be continued from its page.

### Free-tier limits worth knowing

- **Render:** 750 instance hours a month; the sleep above.
- **Netlify:** 300 build minutes a month; proxied requests have a time limit, which the
  build progress screen survives by falling back from its event stream to polling.
- **Atlas M0:** 512 MB of storage.
- **Gemini:** the daily request ceiling in `.env.example` (500 for the pinned model).
  Each kit uses up to 12 calls, and generation is rate limited per user.
